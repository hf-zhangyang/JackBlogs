# 博客文章管理指南

本文档说明如何维护技术博客的分类与文章。**核心原则：目录即分类**——分类结构由文件目录决定，文章文件本身即数据源，不再需要手工维护中央清单。

## 📂 目录结构

```
docs/articles/
├── container/                    # 一级分类目录（目录名 = URL 片段）
│   ├── _meta.md                  # 分类元数据（显示名 / 图标 / 描述 / 排序）
│   └── docker/                   # 二级子分类目录
│       ├── _meta.md              # 子分类元数据（显示名 / 排序）
│       ├── deploy.md
│       └── docker-compose.md
├── linux/
│   ├── _meta.md
│   └── basic-commands/
│       ├── _meta.md
│       └── commands.md
├── backend/
│   ├── _meta.md
│   └── tools/
│       ├── _meta.md
│       └── gitea.md
├── articles.js                   # ⚙️ 由 tools/sync-articles.mjs 自动生成
└── index.md                      # 文章总览页面
```

**URL 规则**：`/articles/<分类目录>/<子分类目录>/<文件名>`

| 文件位置 | 访问路径 |
|---------|---------|
| `docs/articles/container/docker/deploy.md` | `/articles/container/docker/deploy` |
| `docs/articles/linux/basic-commands/commands.md` | `/articles/linux/basic-commands/commands` |

**目录名策略**：目录名只用于 URL（建议英文小写、连字符分隔），中文显示名写在同级 `_meta.md` 的 `title` 里。这样 URL 简洁，页面显示仍是中文。

## 🚀 添加一篇文章

只需两步：

**步骤 1**：把 Markdown 文件放进目标子分类目录

```
docs/articles/container/docker/nginx-proxy.md
```

文件顶部的 frontmatter（全部字段可选）：

```markdown
---
title: Nginx 反向代理配置      # 缺省取正文 H1
desc: 容器化部署 Nginx 与反向代理配置   # 缺省同 title
date: 2026-10-03              # 影响首页「最新文章」排序
order: 10                     # 同组内排序，数字小的在前
---

# Nginx 反向代理配置

正文……
```

**步骤 2**：同步索引

```bash
npm run sync
```

> `npm run dev` 与 `npm run build` 已内置该步骤。开发时新增文章后重启一次 `npm run dev`，侧边栏即可刷新。

## 🗂️ 添加新分类 / 子分类

**新增子分类**（在已有分类下）：

```bash
mkdir -p docs/articles/container/kubernetes
```

新建 `docs/articles/container/kubernetes/_meta.md`：

```markdown
---
title: Kubernetes
order: 2
---
```

**新增分类**：

```bash
mkdir -p docs/articles/database/mysql
```

新建 `docs/articles/database/_meta.md`（分类级元数据）：

```markdown
---
title: 数据库
icon: 🗄️
desc: MySQL、Redis、MongoDB 等数据库的使用和优化。
order: 4
---
```

再新建 `docs/articles/database/mysql/_meta.md` 写子分类显示名，然后放入文章、执行 `npm run sync`。

### `_meta.md` 字段说明

| 字段 | 适用层级 | 必填 | 说明 |
|------|---------|------|------|
| `title` | 分类 / 子分类 | ✅ | 页面显示的中文名，缺省用目录名 |
| `icon` | 分类 | — | 分类图标 emoji，缺省 📘 |
| `desc` | 分类 | — | 分类简介，缺省为「<显示名>相关文章。」 |
| `order` | 分类 / 子分类 / 文章 | — | 排序值，数字小的在前；分类缺省排在最后 |

## 📦 批量导入已有文档

外部工作目录里的 Markdown 可以一次性导入多篇：

```bash
# 多篇文件
node tools/publish.mjs 第一课.md 第二课.md 第三课.md

# 整个目录（递归收集 .md）
npm run publish -- ./drafts/

# 分类也可以走命令行参数
node tools/publish.mjs --category=container --subcategory=docker 某文章.md
```

导入文档的 frontmatter 需要声明分类（支持显示名或目录名）：

```markdown
---
title: 文章标题
category: 容器与运维        # 或填目录名 container
subcategory: Docker        # 或填目录名 docker
desc: 一句话简介
---
```

导入时会自动：落盘到规范位置 → 剥离 `category`/`subcategory` 字段 → 同步索引。
分类不存在时脚本会报错并列出可用分类，不会凭空新建目录。

## 🔍 跳过规则

以下内容不会被扫描为文章：

- 以 `_` 或 `.` 开头的文件与目录（`_meta.md` 即元数据文件）
- `docs/articles/index.md`（总览页本身）
- 直接放在分类目录下、没有归入子分类目录的散装 `.md`（会打印警告并跳过）——**规范只认三级**

## ✅ 验证清单

1. 文件放在 `<分类目录>/<子分类目录>/` 下
2. frontmatter 至少能解析出标题（`title` 或正文 H1）
3. 执行 `npm run sync`，确认输出的分类树与文章数符合预期
4. `npm run dev` 访问 `/articles/` 检查列表，点击文章确认链接不是 404

## ⚠️ 常见问题

### 链接 404

**原因**：文件所在目录层级与链接不一致，或改了目录名后没有重新同步。

**解决**：确认文件在三级目录内，执行 `npm run sync` 后重启 dev。

### 文章不显示在列表里

**原因**：多数是文件放错层级（如直接放在分类目录下），或文件以 `_` 开头。

**解决**：查看 `npm run sync` 的警告输出，按提示移入子分类目录。

### 分类顺序不对

**解决**：调整该分类 `_meta.md` 里的 `order` 值（数字小的靠前）。

### 首页「最新文章」顺序不对

**解决**：首页取全部文章中 `date` 最新的 3 篇，检查各文章的 `date` 字段。

### 改了文章路径，旧链接 404 怎么办

**解决**：在 `docs/.vitepress/theme/legacy-urls.mjs` 的 `LEGACY_MAP` 中补一条映射
（`'旧路径': '新路径'`，站点内路径、不写 `.html`），然后运行：

```bash
npm run test:legacy
```

主题会在 404 页面自动把命中映射的旧链接跳转到新地址。

## 🔧 维护建议

1. **不要手工编辑** `articles.js`——它是生成产物，改动会在下次 `npm run sync` 时被覆盖
2. **目录名用英文**、保持小写与连字符，中文显示名统一写在 `_meta.md`
3. **文件名即 URL**：发布后改名或移动文件会导致旧链接失效
4. **描述风格统一**：一句话说清文章解决什么问题
